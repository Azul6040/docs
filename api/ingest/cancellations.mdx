Use this endpoint to send all cancelled order lines and voids for the shift. Restaurantero Pro tracks cancellations separately from discounts because they represent items that were ordered but never delivered or billed — a key signal for operational issues and potential revenue leakage. When the number or value of cancellations exceeds normal thresholds, the system automatically triggers a `cancellations_high` alert in the operator dashboard. Submit this endpoint after order lines and discounts, but before payments, sales, and the cash register cut.

## Endpoint

```http
POST https://api.restauranteropro.com/api/v1/ingest/cancellations
```

## Required headers

<ParamField header="X-API-Key" type="string" required>
  Your branch API key.
</ParamField>

<ParamField header="X-Idempotency-Key" type="string" required>
  A UUID v4 unique to this cancellations submission. Append a suffix to the cash register cut's identifier, for example: `{CashRegisterOpening.identifier}-cancellations`.
</ParamField>

<ParamField header="Content-Type" type="string" required>
  Must be `application/json`.
</ParamField>

## Automatic alert behavior

Restaurantero Pro analyzes the cancellations you send and automatically compares them against the branch's historical baseline. If the count or total value of cancellations for the day exceeds the normal threshold, the system raises a `cancellations_high` alert (severity: `yellow` or `red`) in the operator dashboard and, if configured, dispatches an `alert.triggered` webhook event.

The system also detects patterns such as a single staff member accounting for a disproportionate share of voids, which surfaces as a `void_alert`.

<Warning>
  The alert thresholds are calculated automatically from historical data. There is no configuration required on your end — just make sure you send all cancellations accurately so the baseline remains reliable.
</Warning>

## Response

### 202 Accepted

The cancellations were received and queued for processing.

<ResponseField name="data" type="object">
  <Expandable title="properties" defaultOpen>
    <ResponseField name="data.type" type="string">
      Always `"cancellations-ingest"`.
    </ResponseField>

    <ResponseField name="data.attributes.queued" type="boolean">
      `true` when the submission has been accepted and queued.
    </ResponseField>
  </Expandable>
</ResponseField>

```json
{
  "data": {
    "type": "cancellations-ingest",
    "attributes": { "queued": true }
  }
}
```

<Tip>
  If your shift had zero cancellations, you can send an empty array: `"cancellations": []`. This signals to Restaurantero Pro that the shift was clean, rather than leaving the data missing.
</Tip>
