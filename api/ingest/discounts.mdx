Use this endpoint to send all discounts and courtesies applied during the shift. Restaurantero Pro uses this data to keep the P&L accurate — discounts reduce net revenue and must be tracked separately from cancellations. Unusual discount patterns also trigger automatic alerts in the operator dashboard. Submit this endpoint after order lines but before payments, sales, and the cash register cut.

## Endpoint

```http
POST https://api.restauranteropro.com/api/v1/ingest/discounts
```

## Required headers

<ParamField header="X-API-Key" type="string" required>
  Your branch API key.
</ParamField>

<ParamField header="X-Idempotency-Key" type="string" required>
  A UUID v4 unique to this discounts submission. Append a suffix to the cash register cut's identifier, for example: `{CashRegisterOpening.identifier}-discounts`.
</ParamField>

<ParamField header="Content-Type" type="string" required>
  Must be `application/json`.
</ParamField>

## Request body

<ParamField body="data" type="object" required>
  Top-level wrapper following JSON:API structure.

  <Expandable title="properties" defaultOpen>
    <ParamField body="data.type" type="string" required>
      Always `"discounts"`.
    </ParamField>

    <ParamField body="data.attributes" type="object" required>
      <Expandable title="attributes">
        <ParamField body="data.attributes.branch_identifier" type="string" required>
          UUID of the branch sending the data.
        </ParamField>

        <ParamField body="data.attributes.date" type="string" required>
          Date of the discount data in `YYYY-MM-DD` format.
        </ParamField>

        <ParamField body="data.attributes.closing_type" type="string" required>
          Type of cut this submission is associated with: `"xout"` or `"zout"`.
        </ParamField>

        <ParamField body="data.attributes.discounts" type="object[]" required>
          Array of discount records applied during the shift.

          <Expandable title="discount object fields">
            <ParamField body="discount_identifier" type="string" required>
              UUID of the discount record in your POS.
            </ParamField>

            <ParamField body="type" type="string" required>
              Discount type. See the discount types table below.
            </ParamField>

            <ParamField body="factor_type" type="string" required>
              Factor type, typically mirrors `type`. See the discount types table below.
            </ParamField>

            <ParamField body="name" type="string" required>
              Display name of the discount (e.g., `"Descuento Empleado"`, `"Cortesía Gerencia"`).
            </ParamField>

            <ParamField body="rate" type="number" required>
              Discount rate or percentage. For `percentage` types, this is the percentage (e.g., `50` for 50%). For `fixed`, this is the fixed amount. For `courtesy`, use `100`.
            </ParamField>

            <ParamField body="amount_cents" type="integer" required>

            </ParamField>

            <ParamField body="applied_to" type="string" required>

            <ParamField body="applied_by" type="string" required>
              Full name of the staff member who applied the discount.
            </ParamField>

            <ParamField body="authorized_by" type="string" required>
              Full name of the manager or supervisor who authorized the discount.
            </ParamField>

            <ParamField body="reason" type="string">
              Free-text reason for the discount (e.g., `"Invitación a cliente VIP"`).
            </ParamField>
          </Expandable>
        </ParamField>
      </Expandable>
    </ParamField>

    <ParamField body="data.meta" type="object">
      <Expandable title="meta fields">

          Name of the POS sending the data.
        </ParamField>

        <ParamField body="data.meta.sent_at" type="string">

        </ParamField>
      </Expandable>
    </ParamField>
  </Expandable>
</ParamField>

## Discount types

| type / factor_type | Description |
|--------------------|-------------|
| `percentage` | A percentage off the order or item subtotal |
| `fixed` | A fixed amount deducted in centavos |
| `courtesy` | A full courtesy — 100% of the amount is waived |

## Response

### 202 Accepted

The discounts were received and queued for processing.

<ResponseField name="data" type="object">
  <Expandable title="properties" defaultOpen>
    <ResponseField name="data.type" type="string">
      Always `"discounts-ingest"`.
    </ResponseField>

    <ResponseField name="data.attributes.queued" type="boolean">
      `true` when the submission has been accepted and queued.
    </ResponseField>
  </Expandable>
</ResponseField>

```json
{
  "data": {
    "type": "discounts-ingest",
    "attributes": { "queued": true }
  }
}
```

<Note>
  Restaurantero Pro tracks the `applied_by` and `authorized_by` fields to detect anomalies — for example, a staff member applying discounts without an authorizing manager. Populate both fields accurately for reliable alert behavior.
</Note>
