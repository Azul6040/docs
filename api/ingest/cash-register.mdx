Use this endpoint to submit a cash register cut to Restaurantero Pro. You can send either a Corte X (`xout`), which is an informational mid-shift close, or a Corte Z (`zout`), which marks the end of the day and triggers the full async regeneration of all intelligence cubes — P&L, food cost, KPIs, and alerts.

<Note>
  Send this endpoint **last** in the ingestion sequence. The Corte Z is the trigger that kicks off processing. Make sure you've already submitted orders, discounts, cancellations, payments, and sales before calling this endpoint.
</Note>

## Endpoint

```http
POST https://api.restauranteropro.com/api/v1/ingest/cash-register
```

## Required headers

<ParamField header="X-API-Key" type="string" required>
  Your branch API key. Format: `rpro_live_xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx` for production, `rpro_test_xxx` for sandbox.
</ParamField>

<ParamField header="X-Idempotency-Key" type="string" required>
  A UUID v4 unique to this cash register cut. Use the `identifier` of the `CashRegisterOpening` record from your POS. If a network failure causes you to retry, reuse the same key — Restaurantero Pro will return the original response without reprocessing.
</ParamField>

<ParamField header="Content-Type" type="string" required>
  Must be `application/json`.
</ParamField>

## Summary types

The `summaries` array accepts any combination of the following `type` values:

| type | Description |
|------|-------------|
| `cash_sales` | Total cash sales |
| `card_sales` | Total card sales (credit + debit combined) |
| `card_credit_sales` | Credit card sales (optional breakdown) |
| `card_debit_sales` | Debit card sales (optional breakdown) |
| `transfer_sales` | Bank transfer / SPEI sales |
| `delivery_sales` | Delivery platform sales (Rappi, Uber Eats, DiDi Food) |
| `voucher_sales` | Despensa voucher sales |
| `tips_received` | Tips collected from customers |
| `tips_paid_to_waiter` | Tips paid out to waitstaff |
| `withholding` | Withheld amount (e.g., moche) |
| `deposits` | Deposits added to the cash fund |
| `cash_variance` | Difference between expected and actual cash — positive = overage, negative = shortage |

## Response

### 202 Accepted

The request was received and queued for processing. Processing happens asynchronously.

## Async processing

The `202 Accepted` response means the data was accepted — not that processing is complete. After a Corte Z, Restaurantero Pro regenerates all daily intelligence cubes (P&L, food cost, KPIs, menu engineering, alerts) asynchronously. This typically completes within a few seconds.

<Tip>
  Subscribe to the `snapshot.completed` webhook event to know exactly when the day's intelligence data is ready to query, without polling.
</Tip>
